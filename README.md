# Учёт прихода — Telegram-бот с мини-аппом

Бот для учёта прихода/ухода сотрудников через Telegram Mini App. Сотрудник отмечает приход и уход кнопками в мини-аппе, админ добавляет сотрудников и смотрит отчёты (в том числе кто опоздал и сколько часов отработано).

## Стек

- **Сервер**: Node.js + TypeScript, Express, [grammY](https://grammy.dev) (бот, webhook-режим), Prisma + PostgreSQL (БД)
- **Мини-апп**: Vite + TypeScript (без фреймворка), стилизован под брендбук Oui Oui

Бот работает через **webhook**, а не long polling — это специально сделано для бесплатного хостинга: сервис может «засыпать» после простоя, и входящее сообщение от Telegram (HTTP-запрос на вебхук) сам его разбудит. Секрет вебхука генерируется заново при каждом старте и тут же переотправляется в Telegram через `setWebhook`, так что пересыпание/рестарт ничего не ломает.

## 1. Создать бота в Telegram

1. Напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, получите токен.
2. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) — он понадобится как ID администратора.

## 2. Завести бесплатную базу данных (Postgres)

Нужен один из бесплатных провайдеров — оба не требуют карты для регистрации:

- **[Supabase](https://supabase.com)** → New Project → в настройках проекта (`Project Settings → Database`) скопировать `Connection string` (режим **Session pooler**, порт 5432 или 6543 — оба подходят)
- **[Neon](https://neon.tech)** → New Project → на дашборде сразу показана строка `Connection string`

Строка выглядит так: `postgresql://user:password@host/dbname?sslmode=require` — это и есть `DATABASE_URL`.

## 3. Задеплоить на Render (бесплатно)

1. Код должен лежать в GitHub-репозитории (могу помочь завести, если ещё не сделано)
2. На [render.com](https://render.com) → **New → Web Service** → подключить репозиторий
3. Параметры сборки:
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm run start -w server`
4. В **Environment** добавить переменные из `.env.example`:
   - `BOT_TOKEN`, `ADMIN_TELEGRAM_IDS`, `TIMEZONE`
   - `DATABASE_URL` — строка из шага 2
   - `PUBLIC_URL` — Render покажет адрес сервиса ещё до первого деплоя (`https://<имя-сервиса>.onrender.com`), впишите его заранее
5. Деплой запустится сам. Проверить логи — на вкладке **Logs** в Render, ошибок про `BOT_TOKEN`/`DATABASE_URL` быть не должно.

Бесплатный инстанс Render засыпает после ~15 минут без запросов и просыпается по первому обращению (несколько секунд задержки) — для внутреннего инструмента это некритично.

## 4. Локальный запуск (для разработки)

```bash
npm install
cp .env.example .env
```

Заполните `.env` так же, как в шаге 3 (можно использовать ту же бесплатную базу Supabase/Neon — она одна на дев и прод, если штат небольшой; либо завести отдельный Neon-проект под разработку).

Для `PUBLIC_URL` локально нужен HTTPS-туннель — Telegram Mini App и вебхук не работают на `localhost`:

```bash
cloudflared tunnel --url http://localhost:3000
```

Полученный `https://*.trycloudflare.com` адрес впишите в `PUBLIC_URL`.

Применить миграции и сгенерировать Prisma-клиент:

```bash
npm run prisma:migrate -w server
```

Собрать мини-апп и запустить сервер:

```bash
npm run build -w webapp
npm run dev:server
```

## 5. Альтернатива: свой VPS вместо Render

Если предпочитаете постоянный сервер без «засыпания» — в репозитории есть `Dockerfile`, `docker-compose.yml` и `Caddyfile` (авто-HTTPS по домену). На VPS с Docker и доменом, указывающим A-записью на IP сервера:

```bash
git clone <репозиторий> && cd <репозиторий>
cp .env.example .env
# заполните .env: BOT_TOKEN, ADMIN_TELEGRAM_IDS, TIMEZONE, DATABASE_URL,
# DOMAIN=ваш-домен.ru, PUBLIC_URL=https://ваш-домен.ru
docker compose up -d --build
```

При этом варианте бот всё равно работает через webhook (код один и тот же) — просто сервис не засыпает, задержек не будет. `DATABASE_URL` при желании может указывать на свой Postgres в docker-compose вместо Supabase/Neon.

## 6. Настройка бота в BotFather

Кнопка «Открыть» в чате с ботом настраивается автоматически — приложение само вызывает `setChatMenuButton` при каждом старте.

## Как это работает

- **Сотрудники**: администратор добавляет ФИО, должность и время начала смены через админ-панель — без Telegram ID.
- **Привязка аккаунта**: при первом открытии мини-аппа сотрудник сам выбирает себя из списка непривязанных имён.
- **Отметка**: кнопки «Я на работе» / «Ухожу с работы» — по одной паре отметок в день, идемпотентно.
- **Опоздания**: сравнение времени отметки прихода с `workStartTime` сотрудника (у каждого своё).
- **Отчёты**: у админа — таблица за сегодня в мини-аппе и выгрузка CSV за произвольный период (дата, ФИО, приход, уход, опоздание, часы).
- **Права админа**: список Telegram ID в `ADMIN_TELEGRAM_IDS` — не обязаны быть сотрудниками (например, управляющий без своей смены).

## Известные ограничения

- Postgres/Render-связка проверена только на уровне логики и типов (генерация миграций под диалект Postgres, структура запросов) — живого Postgres на машине разработки нет, сквозной тест `docker compose up --build` или реальный деплой на Render ещё предстоит прогнать один раз перед тем, как полагаться на это в проде.
- Бесплатный Render "засыпает" — если для вас критичен мгновенный первый отклик, вариант 5 (VPS) устраняет эту задержку.
