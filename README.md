# Учёт прихода — Telegram-бот с мини-аппом

[![CI](https://github.com/davtandilov-tech/ouioui-attendance/actions/workflows/ci.yml/badge.svg)](https://github.com/davtandilov-tech/ouioui-attendance/actions/workflows/ci.yml)

Бот для учёта прихода/ухода сотрудников через Telegram Mini App. Сотрудник отмечает приход и уход кнопками в мини-аппе, админ добавляет сотрудников и смотрит отчёты (в том числе кто опоздал и сколько часов отработано).

## Стек

- **Сервер**: Node.js + TypeScript, Express, [grammY](https://grammy.dev) (бот, webhook-режим), Prisma + PostgreSQL (БД)
- **Мини-апп**: Vite + TypeScript (без фреймворка), стилизован под брендбук Oui Oui

Бот работает через **webhook**, а не long polling — это специально сделано для бесплатного хостинга: сервис может «засыпать» после простоя, и входящее сообщение от Telegram (HTTP-запрос на вебхук) сам его разбудит. Секрет вебхука генерируется заново при каждом старте и тут же переотправляется в Telegram через `setWebhook`, так что пересыпание/рестарт ничего не ломает.

## 1. Создать бота в Telegram

1. Напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, получите токен.
2. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) — он понадобится как ID администратора.

## 2. Завести бесплатную базу данных (Postgres)

Нужен один из бесплатных провайдеров — оба не требуют карты для регистрации:

- **[Supabase](https://supabase.com)** → New Project → в настройках проекта (`Project Settings → Database`) скопировать `Connection string` (режим **Session pooler**, порт 5432 или 6543 — оба подходят)
- **[Neon](https://neon.tech)** → New Project → на дашборде сразу показана строка `Connection string`

Строка выглядит так: `postgresql://user:password@host/dbname?sslmode=require` — это и есть `DATABASE_URL`.

## 3. Задеплоить на Render (бесплатно)

В репозитории есть `render.yaml` — Render прочитает его сам и заполнит build/start-команды и порт, останется только вставить секреты.

1. Код должен лежать в GitHub-репозитории
2. На [render.com](https://render.com) → **New → Blueprint** → выбрать репозиторий → Render найдёт `render.yaml` и предложит создать сервис `ouioui-attendance`
3. Перед применением попросит заполнить переменные, помеченные как секретные:
   - `BOT_TOKEN`
   - `ADMIN_TELEGRAM_IDS`
   - `DATABASE_URL` — строка из шага 2
4. **Apply** — Render соберёт и задеплоит сам. `PUBLIC_URL` заполнять не нужно — сервис сам возьмёт свой адрес через `RENDER_EXTERNAL_URL`.
5. Проверить логи — вкладка **Logs** в Render, ошибок про `BOT_TOKEN`/`DATABASE_URL` быть не должно.

Без Blueprint (вручную через **New → Web Service**) нужно будет самостоятельно указать те же Build/Start Command (`npm install && npm run build` / `npm run start -w server`) и переменные окружения, включая `PUBLIC_URL=https://<имя-сервиса>.onrender.com`.

Бесплатный инстанс Render засыпает после ~15 минут без запросов и просыпается по первому обращению (несколько секунд задержки) — для внутреннего инструмента это некритично.

## 4. Локальный запуск (для разработки)

```bash
npm install
cp .env.example .env
```

Заполните `.env` так же, как в шаге 3 (можно использовать ту же бесплатную базу Supabase/Neon — она одна на дев и прод, если штат небольшой; либо завести отдельный Neon-проект под разработку).

Для `PUBLIC_URL` локально нужен HTTPS-туннель — Telegram Mini App и вебхук не работают на `localhost`:

```bash
cloudflared tunnel --url http://localhost:3000
```

Полученный `https://*.trycloudflare.com` адрес впишите в `PUBLIC_URL`.

Применить миграции и сгенерировать Prisma-клиент:

```bash
npm run prisma:migrate -w server
```

Собрать мини-апп и запустить сервер:

```bash
npm run build -w webapp
npm run dev:server
```

## 5. Альтернатива: свой VPS вместо Render

Если предпочитаете постоянный сервер без «засыпания» — в репозитории есть `Dockerfile`, `docker-compose.yml` и `Caddyfile` (авто-HTTPS по домену). На VPS с Docker и доменом, указывающим A-записью на IP сервера:

```bash
git clone <репозиторий> && cd <репозиторий>
cp .env.example .env
# заполните .env: BOT_TOKEN, ADMIN_TELEGRAM_IDS, TIMEZONE, DATABASE_URL,
# DOMAIN=ваш-домен.ru, PUBLIC_URL=https://ваш-домен.ru
docker compose up -d --build
```

При этом варианте бот всё равно работает через webhook (код один и тот же) — просто сервис не засыпает, задержек не будет. `DATABASE_URL` при желании может указывать на свой Postgres в docker-compose вместо Supabase/Neon.

## 6. Настройка бота в BotFather

Кнопка «Открыть» в чате с ботом настраивается автоматически — приложение само вызывает `setChatMenuButton` при каждом старте.

## 7. Напоминания сотрудникам (необязательно)

Бот может сам писать сотрудникам:
- в 11:30 — тем, кто ещё не отметил приход сегодня;
- в 00:00 — тем, у кого смена открыта (есть приход, но нет ухода).

Поскольку бесплатный Render засыпает без запросов, встроенный таймер внутри приложения ненадёжен — нужен внешний будильник. Используем [cron-job.org](https://cron-job.org) (бесплатно, без карты):

1. Задайте `CRON_SECRET` в переменных окружения (сгенерировать: `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`)
2. На [cron-job.org](https://cron-job.org) → регистрация → **Create cronjob**
3. Первое задание (напоминание о приходе):
   - **URL**: `https://<ваш-сервис>.onrender.com/internal/reminders/checkin`
   - **Request method**: `POST`
   - **Schedule**: каждый день в `11:30`, часовой пояс — `Europe/Moscow`
   - В **Advanced → Request headers** добавить: `X-Cron-Secret: <значение CRON_SECRET>`
4. Второе задание (напоминание об уходе) — то же самое, но:
   - **URL**: `.../internal/reminders/checkout`
   - **Schedule**: `00:00`, `Europe/Moscow`

Оба запроса заодно будят «уснувший» сервис Render — время первого срабатывания после сна может занять до минуты.

## 8. Мониторинг (необязательно)

`/healthz` делает реальный запрос к БД (не просто "процесс отвечает") — удобно повесить внешний пинг с алертом:

1. На том же [cron-job.org](https://cron-job.org) → **Create cronjob**
2. **URL**: `https://<ваш-сервис>.onrender.com/healthz`, **Schedule**: каждые 15 минут, метод `GET` (заголовки не нужны)
3. В **«Уведомить меня когда...»** включить **«запуск cron задания провален»** — придёт email, если бот/база упадут

Заодно эти пинги держат бесплатный Render почти всегда «тёплым».

## Как это работает

- **Сотрудники**: администратор добавляет ФИО и должность через админ-панель — без Telegram ID и без времени смены.
- **Привязка аккаунта**: при первом открытии мини-аппа сотрудник сам выбирает себя из списка непривязанных имён и указывает время начала своей смены. Админ может позже поменять его вручную.
- **Редактирование**: в таблице админ-панели — «изменить» (ФИО/должность/время) и «отвязать» (сбросить Telegram-аккаунт, например если сотрудник потерял доступ к телефону).
- **Отметка**: кнопки «Я на работе» / «Ухожу с работы» — по одной паре отметок в день, идемпотентно. Все админы получают сообщение в Telegram при каждой отметке.
- **Опоздания**: сравнение времени отметки прихода с `workStartTime` сотрудника (у каждого своё).
- **Отчёты**: у админа — таблица за сегодня, инлайн-просмотр и выгрузка CSV за произвольный период (дата, ФИО, приход, уход, опоздание, часы) с суммой часов по каждому сотруднику.
- **Напоминания**: см. раздел 7 — приход в 11:30, уход в 00:00 (не привязано к календарному дню, чтобы не терять смены, открытые накануне).
- **Права админа**: список Telegram ID в `ADMIN_TELEGRAM_IDS` — не обязаны быть сотрудниками (например, управляющий без своей смены).

## Тесты

```bash
npm test
```

Юнит-тесты (`node:test`, без внешних зависимостей) на нормализацию времени, расчёт опозданий и часов — та логика, которую сложнее всего заметить сломанной вручную. Прогоняются в CI после каждой сборки.

## Известные ограничения

- Docker-путь (VPS, раздел 5) проверен только логически (сборка образа пошагово сверена вручную, `docker build` целиком не прогонялся — на машине разработки нет Docker). Перед первым продакшен-деплоем на VPS стоит один раз прогнать `docker compose up --build`.
- Бесплатный Render "засыпает" — если для вас критичен мгновенный первый отклик, вариант 5 (VPS) устраняет эту задержку.
